Directorio de miembros en WordPress

Como publicar los miembros de una camara CamaraVirtual (por ejemplo cv-105, Hispanotec) dentro de una pagina de WordPress.

1. La fuente de datos

Cada camara expone un endpoint publico, de solo lectura, con sus miembros activos:

GET https://aiagent.ringlypro.com/cv-105/api/public/members
GET https://aiagent.ringlypro.com/cv-105/api/public/members/facets

Parametros opcionales: page, limit (1-100), search, sector, country.

Privacidad. Este endpoint NO devuelve correos ni telefonos. Solo publica: nombre, empresa, pais, sector, sub-especialidad, anos de experiencia, idiomas, bio, LinkedIn, sitio web, tipo de membresia, rol de gobernanza, estado de verificacion y trust score. Los correos siguen protegidos detras de GET /members, que exige autenticacion.
El directorio publico es opt-in por camara. Solo responde si la fila de la camara tiene theme_config.public_directory = true. Ya esta activado para cv-105; las demas camaras devuelven 403 hasta que se active explicitamente.

2. Opcion A — Bloque HTML (5 minutos, sin plugins)

En la pagina de WordPress, agrega un bloque HTML personalizado y pega esto:

<div data-cv-directory
     data-slug="cv-105"
     data-lang="es"
     data-limit="24"
     data-join-url="https://www.camaravirtual.app/cv-105/signup-member"></div>
<script src="https://aiagent.ringlypro.com/embed/chamber-directory.js"></script>

Eso es todo. El widget trae buscador, filtro por sector, tarjetas y paginacion, hereda la tipografia del tema y se adapta a modo oscuro.

AtributoDescripcion
data-slugObligatorio. Slug de la camara, ej. cv-105.
data-langes o en. Predeterminado es.
data-limitMiembros por pagina, 1-100. Predeterminado 24.
data-search0 oculta la barra de busqueda y filtros.
data-join-urlURL del boton "Unete". Omitelo para ocultarlo.
data-baseOrigen del API. Predeterminado https://aiagent.ringlypro.com.

2. Opcion B — Shortcode PHP (recomendado para SEO)

La opcion A renderiza con JavaScript, asi que Google puede tardar en indexar los nombres. Si quieres que los miembros aparezcan en el HTML que recibe el buscador, instala el shortcode:

Ver / descargar el archivo PHP completo

  1. Copia el contenido en wp-content/plugins/cv-directory/cv-directory.php y activalo en Plugins (o pegalo en el functions.php del tema hijo, o en el plugin Code Snippets).
  2. En cualquier pagina o entrada, escribe:
[cv_directory slug="cv-105"]

Atributos: slug, limit, lang, sector, country, base, cache (segundos, predeterminado 300).

[cv_directory slug="cv-105" lang="es" limit="48" sector="tecnologia"]

El shortcode cachea la respuesta con un transient de WordPress, asi que las visitas no golpean el API en cada carga.

3. Si prefieres no tocar nada del tema

Tambien puedes incrustar el dashboard completo en un iframe, pero pierde SEO y obliga a iniciar sesion:

<iframe src="https://www.camaravirtual.app/cv-105"
        style="width:100%;height:900px;border:0" loading="lazy"></iframe>

Para un directorio publico, la Opcion A o B es mejor en todos los aspectos.

4. Activar otra camara

Para exponer el directorio de otra camara, marca la fila en la base de datos:

UPDATE chambers
SET theme_config = COALESCE(theme_config,'{}'::jsonb) || '{"public_directory": true}'::jsonb
WHERE slug = 'cv-XXX';

El resolutor de camaras cachea 60 segundos, asi que el cambio se ve al minuto.

Direccion inversa: WordPress como sistema de registro

Cuando los miembros VIVEN en WordPress y CamaraVirtual debe seguirlos.

Todo lo anterior publica el directorio hacia afuera. Este bloque es lo contrario: WordPress es el dueno de la identidad y el perfil del miembro, y la camara se sincroniza contra el. Las dos direcciones son independientes; una camara puede usar una, las dos o ninguna.

Reparto de responsabilidades. WordPress posee identidad y perfil. CamaraVirtual sigue siendo dueno de lo que se gana dentro de la camara: proyectos, RFQs, mensajes, trust_score, verified, governance_role y access_level. Una sincronizacion nunca escribe esas columnas.
WordPress no puede otorgarse permisos. access_level y governance_role estan excluidos a proposito de los campos sincronizables: un WordPress comprometido o mal configurado no debe poder crear un superadmin de la camara. Ademas nunca se borra a nadie — quien desaparece de WordPress pasa a inactive, porque los miembros son autores de proyectos y mensajes.

Paso 1 — Instalar el conector en WordPress

Ver / descargar el plugin conector. Guardalo como wp-content/plugins/camaravirtual-connector/camaravirtual-connector.php, activalo, y en Ajustes > CamaraVirtual pon el slug de la camara y genera un secreto compartido.

El conector expone /wp-json/camaravirtual/v1/members (firmado con HMAC, no es publico), empuja cada alta/edicion/baja de usuario a la camara, y agrega el shortcode [cv_login] para entrar al panel con un clic.

Si usas MemberPress, Paid Memberships Pro, WooCommerce o ACF, mapea sus campos con el filtro cv_sor_member — hay un ejemplo al final del archivo.

Paso 2 — Configurar la camara

Con un token de administrador de la camara:

PUT /cv-105/api/wp/config
Authorization: Bearer <token de admin>

{
  "enabled": true,
  "mode": "plugin",
  "site_url": "https://hispanotec.org",
  "shared_secret": "<el secreto generado en WordPress>",
  "allow_sso": true,
  "deactivate_missing": false
}

El secreto se guarda cifrado (AES-256-GCM) y nunca se devuelve: la lectura solo dice si esta puesto y sus ultimos 4 caracteres. Enviar el campo vacio conserva el valor guardado.

Si no quieres instalar nada en WordPress, usa "mode": "wp_users" con auth_user + auth_secret (una Application Password de WordPress). Funciona sin plugins, pero solo trae lo que expone wp/v2/users: sin empresa, sin sector, sin telefono.

Paso 3 — Ensayar antes de aplicar

POST /cv-105/api/wp/test              # solo prueba la conexion, no escribe nada
POST /cv-105/api/wp/sync  {"dry_run": true}   # devuelve el plan: que crearia, actualizaria y desactivaria
POST /cv-105/api/wp/sync  {}                  # aplica
GET  /cv-105/api/wp/runs              # historial de sincronizaciones
Corre siempre el dry_run primero y lee el plan. La primera sincronizacion contra un directorio real es el momento con mas riesgo de duplicar o desactivar gente por un mapeo de campos equivocado.

deactivate_missing viene apagado. Enciendelo solo cuando el dry_run demuestre que WordPress ya tiene a todos. Los administradores de la camara y el dueno quedan protegidos aunque este encendido, para que una mala sincronizacion no deje a nadie fuera del panel.

Paso 4 — Tiempo real e inicio de sesion

Con el conector instalado ya no hace falta esperar la siguiente sincronizacion: WordPress notifica cada cambio a POST /cv-105/api/wp/webhook, autenticado por HMAC con ventana de 5 minutos.

Y como los miembros creados por sincronizacion no tienen contrasena utilizable, entran por SSO. Pon esto en cualquier pagina de WordPress:

[cv_login label="Entrar a la camara"]

Genera un enlace firmado, de un solo uso, valido 5 minutos, que abre el panel de la camara ya autenticado. Tambien sigue funcionando el flujo normal de recuperar contrasena.
